workflow itself failing after merge (build, packaging, auth, artifact upload, or the deploy step),
since every other label in this histogram represents a defect caught before the change merged to
`main`. A `cd` failure is **not** a claim that a confirmed defect reached a live user — it typically
means the previous version stayed live and nothing new shipped. Both weeks with data show 0 `cd`
issues (0%): every release that merged this period also deployed successfully.

were caught at the `design` stage — i.e. during the pre-implementation solution-design review
loop, before any code was written. This is the shift-left pattern working as intended: issues
found and fixed before implementation are cheaper than issues found later.
